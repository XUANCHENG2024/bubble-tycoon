## 二、四条必须记住的平衡教训

这一节是本次实施最值钱的产出——**每一条都是 sim 跑出来才发现的**。

### 教训 1：sim 的脚本 AI 对现金余额是**离散响应**的，别信「涨了 8pp」

新系统上线后，标准口径 40 局跑出 normal 从 94% 涨到 102%、hard 从 74% 涨到 84%。看起来是"新增系统偷改了难度"。

但关卡奖金全通也只有 ~400 元，占一局净资产（38000）的 1% —— **1% 的钱不可能带来 8pp**。

于是加了一组对照实验（`tools/diag-balance.js`）：把关卡奖励换成「每天固定 +14 元」这种**与关卡机制完全无关**的补贴。

| 对照组 | normal | hard |
| --- | --- | --- |
| 基线（新系统全关） | 96% | 74% |
| 仅每日固定 +14 元（与关卡无关） | 96% | 73% |
| 仅关卡奖励（金额几乎相同） | 96% | 75% |

**两者一模一样**。原因在 sim 的 AI 上：它的营销/投资判断写死在 `cash > 2500` / `cash > cost*1.6` 这类阈值上，多几百块钱就可能让整条经营路径分叉，收益被放大好几倍。

> **规则**：往经济里加钱之后，"达标率变了"这句话**必须**先用「等额无关补贴」做对照，
> 分清是收入本身的影响还是测速器的路径伪影。这一次真正的漂移是 ±4pp，不是 8pp。

### 教训 2：特殊顾客**顶替**常规顾客 = 在产能紧张时净亏

初版特殊顾客是"顶替"一位常规顾客（总客流不变）。结果 **easy 难度掉了 11pp**（配对逐局相减，19 局变差 vs 11 局变好），而 hard 反而 +2pp —— **难度之间表现相反**。

根因不是口碑奖惩，是顶替机制本身：

```
被挤掉的是「本来能服务好」的客人
  → 特殊客人自己又因耐心低而流失
  → 白丢一单 + 顾客体验变差
```

而玩家在 26 秒里其实**无法"优先伺候"谁**——所有工位并行，流失往往不是选择问题，是产能问题。

改法试了三种：

| 方案 | easy | hard | 结论 |
| --- | --- | --- | --- |
| ① 顶替（初版） | −11pp | +2pp | 差 |
| ② 额外到店（总客流 +1/天） | +1pp | **+5pp** | 也差 —— 客流总量变了就是会改难度（hard 目标高，每天多 1 位客人 ≈ 80 元，30 天 ≈ +2400 元 ≈ +5pp） |
| ③ **1:1 替换**（最终） | ±0 | ±1 | ✓ |

最终还配了两条数值修正：每天配额 2 位 → 1 位；耐心/口碑系数调到**不低于**常规顾客；`repBad` 只留给"评论家"（自带判断的那种），大单与熟客改成纯收益。

> **规则**：任何"换掉一个既有对象"的新增机制，都要先问一句
> 「被换掉的那个东西本来能贡献什么」。答案是"不少"的时候，这就是净亏设计。
> 而且**难度越大越容易触发**（产能越紧张），失败会集中在最不该被惩罚的难度上。

### 教训 3：招牌门槛定得太低，"跨局长期追求"名存实亡

初版门槛 60 / 150 / 300 杯，sim 连玩曲线一跑：

```
第 1 局  Lv.3     ← 一局就满级了
```

脚本 AI 一局卖 1500~2500 杯，摊到 6~8 款上也有一款能过 300 —— 跨局继承完全没意义。

提到 250 / 700 / 1500 之后：

```
第 1 局  Lv.1  →  第 2 局 Lv.2  →  第 4 局 Lv.3
```

顺带发现 sim.js 里的等级显示**写死了一份阈值副本**（60/150/300），门槛改了它不跟着改，一直误报 Lv.3。

> **规则**：配置值**只留一份**。工具脚本里需要读它时就从引擎导出，
> 不要抄一份 —— 抄的那份一定会忘记同步，而且报错方向是"看起来更糟"。

### 教训 4：`report` 构建早于关卡结算，结算结果要**回填**

和第一批的合同是同一个坑（见第一批记录）：`endDay()` 里 `s.report` 先构建，关卡结算后做。关卡奖励要进日报，就必须回填进 `s.report.stageResult`。

```js
const sr = settleStage(s);
if (sr) {
  s.stageResult = sr;
  if (s.report) s.report.stageResult = sr;   // ← 少了这行，日报里就没有关卡结算行
}
```

另外顺手修了一个**逻辑缺陷**：结局四维的「服务」维度在零样本时把满意率兜底成 1，结果破产局（0 单 0 流失）会拿到"服务 · 五星好评"这种自相矛盾的称号。零样本应该是 0。

### 教训 5：结局「经营」维度的归一化方向写反了，称号永远拿不到

四维评级里的「经营」维度按累计杯数评定。初版按难度目标归一化：

```js
scale: totalCups / (goal / 300)     // normal: goal=38000 → 分母 127
```

`ENDING_AXES` 里的阈值是 600 / 1500 杯，乘上去就变成 **76000 / 190000 杯** ——
而实测一局才卖 2600 杯左右。**这个称号一局都拿不到，整个维度形同虚设**。

修法：难度的差异体现在**单杯利润**（目标金额不同）而不是杯数 ——
实测三档难度的累计总杯数其实很接近（easy ~2700 / normal ~2644 / hard ~3020），
所以经营维度直接用**固定**杯数阈值：1500 杯 = 街角名店、3000 杯 = 连锁巨头。

> **规则**：给"规模型"指标做难度归一化之前，先测一测**各难度的实际量级差多少**。
> 差得不多就别归一化（归一化只会放大误差）；差得多再归一化，
> 而且必须验算「归一化后的门槛 vs 实测量级」—— 一个永远达不到的称号
> 和没有这个称号没有区别。

## 三、两个真实的 UX 缺陷（被新内容放大后暴露）

### ① 小游戏端：引导高亮指向屏幕外的元素，玩家根本点不到

备货页内容高度是**随机的**（今日任务条数、今日建议条数、菜单行数都变）。
引导第④步要玩家「点一下任意配方卡」，但配方行可能落在可视区外：

- 命中区在裁剪区外**不会被登记**（`GFX.addHit` 的既有行为）→ 点了没反应
- 高亮框也画在屏幕外 → 玩家根本不知道要点哪

备货页加了一张关卡卡（+66px）后更容易触发（minigame-smoke 随机失败 5~6 项）。

**修法**：加了 `tutFollowScroll()` —— 引导进行中时，每帧检查高亮矩形是否在裁剪区内，超出就调整该 tab 的滚动量。顺带修了一个连带问题：`VIEW.tut.rect` 原来只在切步时算一次，而 `panelRects` 每帧都变，两者会错位（高亮指向 192、采购卡却画在 −130）。

> **规则**：引导指向的元素**必须**在可视区内。这是引导的底线，
> 不能靠"玩家自己滚一下"来解决 —— 新手不知道要滚。

### ② 两版招牌卡的高度：内容不能把主要交互挤出首屏

- **小游戏端**：招牌卡最初 10 行（300px），把配方行整个推出首屏。
  改成**两列排布 + 只显示「已成招牌 / 有进度」的配方**（0 杯的既没信息又占地方），压到最多 5 行。
- **H5 端**：招牌卡放在**研发页**（不是备货页）—— 那里本来就是"看配方"的地方，招牌进度是配方的属性，不是备货信息。

```

dom-smoke     ✅        browser-smoke  ✅ 122（+11：第二批 UI 落地）

```

| 口径 | 第一批后 | 第二批后 | 说明 |
| --- | --- | --- | --- |
| **配对差值**（全开 − 全关，30 局同种子） | — | **easy ±0 / normal +3 / hard +2** | ← 真实漂移 |
| 标准口径 easy / normal / hard（40 局） | 180 / 94 / 72 | 169~183 / 97~100 / 74~76 | sim 的 AI 用 `Math.random()`，每次运行结果不同，取多轮区间 |
| 连玩曲线（8 局） | 96→96（平） | **102→111（平，微升）** | 无衰减 |
| 招牌等级曲线（8 局） | — | Lv.1 → Lv.2 → Lv.3 | 需要专精 + 连打多局 |

**为什么以配对差值为准**：标准口径每次跑的结果能差好几个百分点
（easy 的 40 局里有 1~2 局接近破产线，单局就能拉动 1% 的均值），
而配对口径用**同一套随机序列**跑全开与全关两个版本，逐局相减，
路径伪影（教训 1）和采样噪声都被抵消掉了。

配对口径的 +3pp（normal）与第一批合同的 +2pp 同量级 —— **新增四个系统没有偷改难度**。

**关于招牌加成**：它是**乘性/小额**的（销量权重 +6~20%、售价 +¥0~2、每杯省 ¥0~0.30），
不额外发钱 —— 这是第一批教训 1 的直接应用。
但它**跨局继承**，所以必须进连玩曲线一起测（`sim.js --chain` 现在会把招牌进度带进下一局）。

## 五、回归锁

- **probe J 组 35 项**：
  - J1 关卡：章节划分（6 章 × 5 天 = 30 天）、三档难度门槛/奖励递增、切难度生效、
    达成发钱 + 记录通关 + 自动推进下一关、**未达成不扣口碑**、存档清洗（假关卡 id / 非法难度档）
  - J2 招牌：跨局基线立刻生效、加成进定价与成本、继承数据里不存在的配方 id 被丢弃、
    **合并只加本局新增**（100+30=130，不是 100+100+30）、每日挑战不写回 META
  - J3 特殊顾客：能被 `customerTypeById` 查到、不混进常规客群表、每天最多 1 位、
    **1:1 替换（总客流不变）**、服务评论家给口碑、大单与熟客 repBad 为 0
  - J8 结局：四维齐全、评级正确、综合称号取最高档、**全零数据不虚报称号**、阈值递增
- **browser-smoke 11 项**：关卡卡渲染 + 三个难度按钮 + 切难度奖励提高、
  研发页招牌卡 + 等级名称 + 配方卡徽章、结局页四维称号区
- **minigame-smoke N25 8 项**：三个难度按钮在命中区、关卡卡登记了面板矩形、
  切难度奖励提高、招牌卡列出有进度的配方、招牌等级生效、结局四维数据

**新增工具**：`tools/diag-balance.js` —— 逐个关掉新系统做**配对比较**，
并带一组「等额无关补贴」作为噪声底。这是以后加任何经济系统都该先跑一遍的东西。
