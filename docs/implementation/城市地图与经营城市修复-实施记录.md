# 经营城市点击无响应修复 + 城市地图（V13）

> 两件事：① 修一个**已经存在很久**的静默 bug；② 新增城市地图界面。

---

## 一、缺陷定位与修复

### 现象

小游戏端「经营城市」的「市 xxx ▸」按钮点了没反应 —— 不切换、不报错、连 toast 都没有。

### 排查过程

| 排查项 | 结果 |
|---|---|
| 事件是否注册 | ✅ `doAct` 里有 `vcityNext` 分支 |
| 命中区是否存在 | ✅ 存在（`vcityNext@236`） |
| 层级遮挡 | ❌ 无 |
| 禁用状态 | ❌ 无 |
| **状态判断 / 逻辑** | ✅ **找到根因** |

用探针实测：点击后 `venue.cityId` **纹丝不动**（110100 → 110100），且无 toast ——
说明 `doAct` 被调用了，但 `nextCity()` 返回的结果没生效。

### 根因

```js
const list = citiesOfProvince(v.provId);   /* 北京 → ['110100'] */
const i = list.findIndex(c => c.id === v.cityId);   /* 0 */
const c = list[(i + 1 + list.length) % list.length];  /* (0+1+1)%1 = 0 */
```

**直辖市/特别行政区只有 1 个市**（北京、天津、上海、重庆…），
循环 `(i+1) % list.length` 在长度为 1 时**永远回到自己** ——
既没有换城市，也没有"已到末尾"的分支，所以是**完全静默**的。

**而默认经营城市恰恰就是北京** —— 新玩家第一次点就中招，且永远不知道为什么。

实测确认：

```
省 11 → 1 个市: 北京市          ← 循环原地打转
省 51 → 18 个市: 成都市、自贡市…  ← 正常
```

### 修复

**1. `nextCity()`：省内只有 1 个城市时，跨省继续找**

```js
if (list.length === 1) {
  /* 跨省找下一个「有多个市」的省 */
  for (let k = 1; k <= PROVINCES.length; k++) { ... }
}
```

找不到时给出明确提示（「该省只有一个城市，可先切换省份」）而不是静默无效。

**2. `nextProvince()`：切到直辖市时说明「市不会变」**

切到直辖市时**省变了、市没变**（该省本来就只有这一个市）。
只播城市名会让玩家以为没生效，所以补上 `msg`：

```js
msg: single ? `已切换到${p.name}（该省仅 1 个市）` : ''
```

**3. 两端都播 `msg`**

Canvas 端原来只播 `rvp.cityName`，把 `msg` 丢了。

**4. H5 端补提示**

H5 端用真 `<select>`，**没有这个 bug**（下拉能直接选任意城市）。
但选直辖市时城市下拉只有 1 项，玩家会困惑 → 加一行说明。

### 回归锁

probe **T 组 T1/T2** 专门守这条：

```
T1b  逐个遍历 34 个省，验证「点下一个城市」一定会换城市
T2a  切省必须生效
T2b  切到直辖市时必须有说明文案
```

**「逐省遍历」比「测一个省」强得多** —— 原来只测默认的北京，
换个初始城市就测不出来了。

## 二、城市地图（V13）

### 地图画什么

`CITY_CENTERS` 只收录了 **44 个城市的 GCJ-02 精确坐标**（覆盖 31/34 个省），
而 272 个市都能经营。

**为什么不补齐 272 套坐标**：坐标是**合规数据**（GCJ-02 口径，
见 `data.js` 的说明 —— GCJ-02/BD-09/WGS-84 混用会让门店定位落到隔壁街区），
用插值或近似值糊弄是错的。

所以地图 = **「有精确坐标的城市」+「按省聚合的完整信息」**：
省份信息是完整的（34 省 / 272 市都在），只是没坐标的城市不画点。

### 投影

经纬度**分别**归一化（不用单一缩放因子）：

```js
pt.x = (pt.lng - minLng) / spanLng;      /* 0=西 1=东 */
pt.y = 1 - (pt.lat - minLat) / spanLat;  /* 0=南 1=北 */
```

中国境内经差约 62°、纬差约 50°，若按经度等比缩放，
高纬度城市会明显偏西 —— 地图形状会失真。

### 两版的呈现形态不同（按平台约束）

| | H5 | 小游戏 |
|---|---|---|
| 形态 | 地图**直接铺在页面**上 | **入口条 + 弹窗** |
| 理由 | 页面可滚动，没有这个问题 | 一屏只有约 600px |

★ Canvas 端最初也把地图铺在页面上，结果**店铺页的开店/注资/升级按钮命中区全变 0** ——
`GFX.addHit` 在裁剪区外不登记，超出部分**画出来了但点不到**。
这是本项目在 Canvas 端反复踩过的坑（招牌卡、研发树、出杯位都栽过）。

所以 Canvas 端改成「入口条（44px）+ 弹窗（可滚动）」。
**信息与功能两版对等，呈现形态按各自平台的约束调整。**

### 入口设计

```
🗺️ 城市地图
   [SVG 散点图]              ← H5：直接铺开
   📍 北京市 · 巴蜀麻辣系     ← 当前城市信息
   [🗺️ 切换城市]              ← 打开城市选择器
   省份概览（34 省）
```

**为什么地图之外还要城市列表**：
地图只画 44 个点，而 272 个市都能经营。
只给地图当入口，玩家会以为"只能在这 44 个城市里选"。
所以**地图是可视化入口，列表才是完整入口**。

H5 端列表按省份分组（272 个市平铺要找很久）；
Canvas 端用「循环切换」+ 提示"完整 272 市见经营信息"。

### 顺带修的 xss-verify 假阳性

城市地图用 `<svg>` 绘制，而攻击 payload 里恰好也有 `'<svg onload=alert(1)>'` ——
检测器统计**所有** `<svg>` 元素，把**我们自己画的地图**误判成注入。

**修法不能是「排除所有 svg」**（那会让真的 `<svg onload=...>` 漏过）。
精确判据：只统计**没有 class 的** svg（注入是裸 `<svg>`，
我们的地图 svg 带 `class="map-svg"`），且**任何带事件属性的 svg 都算注入**。

> 假阳性也要修 —— 一个长期误报的测试，会训练人忽略红色。

### 关键验证点（可逐项复核）

1. **点「经营城市」一定换城市** —— probe T1b 遍历 34 个省逐个验证
2. **地图上能切城市** —— browser-smoke「从地图可切换经营城市」
3. **Canvas 端点城市按钮真的换** —— minigame-smoke 断言 `110100 → 130100`
4. **地图 44 个点都可点** —— 两端都验证命中区数量 ≥ 40
5. **列表给全量 272 市** —— browser-smoke「城市选择器列出全部 272 个市」
6. **注入仍被拦截** —— xss-verify 4 组 payload 全部未得逞（修假阳性后仍有效）
