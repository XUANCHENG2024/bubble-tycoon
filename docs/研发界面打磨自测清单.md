# 研发界面打磨（V18）· 自测清单

> 自动化检查覆盖的是**可量化的部分**（可访问性属性、设计令牌、响应式断点、交互状态）。
> 下面这份清单是**自动化测不了、必须人眼/真机确认**的部分。

## 一、诊断结论：哪些不用改

先说**不用改**的，避免为了改而改：

| 项 | 实测 | 结论 |
|---|---|---|
| 配色一致性 | JS 里硬编码颜色 **0 处**，全走 CSS 变量 | ✅ 已统一 |
| 对比度 | `--txt3` 4.91:1、`--red` 5.86:1，其余 AAA（≥7:1） | ✅ 全部达标 |
| 字号 | 内联 `font-size` 仅 3 处，都用 `var(--fs-*)` | ✅ 已统一 |

**真问题**（按优先级）：

| 优先级 | 问题 | 证据 | 影响 |
|---|---|---|---|
| P0 | 折叠头是 `div[data-act]` | 16 个 div 挂 data-act，不可聚焦 | **键盘用户无法折叠** |
| P0 | 无空状态 | 树为空时 = 白屏 | 不知道发生了什么 |
| P1 | 无横向溢出保护 | `body`/`#app` 都没有 | 窄屏可能出横向滚动 |
| P1 | 断点只有 640/340 | 缺 390/768/1024 | 主流手机宽度无专属规则 |
| P1 | aria 属性 0 个 | role 1 / 949 个元素 | 读屏软件无法理解结构 |
| P2 | 圆角 22 种 | 9px(33次)、var(--r1)(18)、8px(14) | **无法统一改** |

## 二、改动清单

### P0 可访问性
- 分组头 `div` → **`<button>`**：一次性拿到可聚焦 / Enter+Space / 读屏播报 / 原生 role
  （比手加 `role="button" tabindex="0"` 可靠 —— 原生语义不会漏）
- 补 `aria-expanded`（32 个）、`aria-controls`（16 个）、`role="tablist"`
- 全局 `:focus-visible` 焦点圈（**用 `:focus-visible` 而非 `:focus`** —— 后者会让鼠标用户每点一下都看到框）
- CSS 重置 button 默认样式（`border`/`background`/`font`/`text-align`）—— 不重置会显示成灰色凸起方块
- 空状态：说明「发生了什么 / 为什么 / 下一步」三件事

### P1 布局与响应式
- `overflow-x: clip` 全局兜底（**不是 `hidden`** —— `hidden` 会连 `position:sticky` 一起干掉，而导航条正是 sticky）
- `@supports not (overflow-x: clip)` 降级到 hidden
- 补 3 个断点：390（iPhone 主力）/ 768（平板，2 列→3 列 + 限宽 900px）/ 1024（桌面，导航条换行不横滑）

### P1 交互状态
- `:active` 按下反馈（**触屏必需** —— 之前只有 hover，触屏上 hover 根本不触发）
- 禁用态统一：不透明度 + 去阴影，`cursor: not-allowed`
  （**不用 `filter: grayscale`** —— 那会连带降低文字对比度）
- 全局尊重 `prefers-reduced-motion`

### P2 设计令牌
新增 10 个令牌，收敛研发界面全部圆角：

```
--r-xs 6px  --r-sm 8px  --r-md 12px  --r-lg 18px  --r-xl 26px  --r-pill 99px
--sp-1 4px  --sp-2 7px  --sp-3 11px  --sp-4 16px
```

`--r1/--r2/--r3` 改为指向新令牌的**别名**，避免动全仓。

**研发界面裸 px 圆角：9 → 0**

## 三、自测清单

### A. 键盘可达（自动化已覆盖，真机需确认手感）

- [ ] `Tab` 能依次走到分组头 / 导航 chip / 研发按钮
- [ ] 分组头聚焦时有**青色焦点圈**，且不被裁掉
- [ ] `Enter` / `Space` 都能展开收起分组
- [ ] `Enter` 能触发研发按钮
- [ ] 鼠标点击时**不**出现焦点圈（`:focus-visible` 的意义）

### B. 多屏自测（自动化测不了真实布局）

| 尺寸 | 设备 | 看什么 |
|---|---|---|
| 320×568 | iPhone SE 1 | 最窄：卡片不溢出、导航 chip 可横滑 |
| 360×640 | Android 常见 | 同上 |
| **390×844** | iPhone 13/14 | **主力**：2 列卡片、间距是否舒适 |
| 414×896 | iPhone 11 | 略宽：是否仍 2 列（应该还是，768 才变 3 列）|
| 768×1024 | iPad 竖屏 | **切到 3 列**，正文限宽 900px 是否居中 |
| 1024×768 | iPad 横屏 | 导航条换行是否自然 |
| 1440×900 | 桌面 | 3 列 + 正文不拉伸 |

**每一档都要看**：
1. 有无横向滚动条（**整页不能横滚**，但导航条内部可以）
2. 配方卡是否等宽对齐
3. 分组头的箭头是否右对齐、不被内容挤走

### C. 视觉一致性
- [ ] 配方卡圆角一致（不再有 7px/8px/9px 混杂）
- [ ] 标签/chip 都是胶囊形
- [ ] 卡片内间距一致（看研发页与经营页是否同一套节奏）

### D. 交互状态
- [ ] 研发树为空时显示空状态（图标 + 说明 + 下一步指引）
- [ ] 禁用按钮（不在本店/ 没解锁/ 缺料/ 钱不够）样式一致，且**能看出为什么**
- [ ] 按下有缩放反馈，松开恢复
- [ ] 系统开启「减少动态效果」时，动效消失但功能正常

### E. 读屏（可选，但建议）
- [ ] 分组头播报「按钮，已折叠/已展开」
- [ ] 导航条播报为「选项卡」

## 五、已知限制

- **jsdom 没有布局引擎**，`getBoundingClientRect` 全返回 0 ——
  断点是否真的切换、`overflow-x: clip` 是否生效，**自动化测不了**，必须真机。
- `prefers-reduced-motion` / `overflow: clip` 在旧浏览器上走降级路径，未实测。
- 只收敛了**研发界面**的圆角；其他页面还有裸 px（有意为之 —— 全仓替换风险大于收益）。
