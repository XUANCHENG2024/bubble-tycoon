# 界面适配验证指南（V20.7）

> 本文覆盖**多分辨率预览**（自动化）与**真机调试**（手工）两条路径。
> 前者可随时跑，后者是上架前必须做的。

## 一、自动验证（一条命令）

```bash
node tools/diag-canvas-layout.js
```

**它做什么**：在 11 种真实设备尺寸下**真实渲染**整个 UI，拦截每一次 Canvas 绘制调用，
然后检查三类问题：

| 判据 | 抓什么问题 | 为什么可靠 |
|---|---|---|
| **横向越界** | 元素超出左右边界 | 横向**没有滚动条**，超出就永远看不到 |
| **固定元素被安全区遮挡** | 底部按钮被 Home 指示条盖住 | 只检查**裁剪区之外**的元素（面板内容会滚动，被裁掉是正常的）|
| **文字被截断** | 容器太窄导致信息丢失 | 看文本是否以 `…` 结尾 |

**覆盖的设备**：

```
小屏 320×568 · 主流 375×667 · 大屏 414×896 · 刘海 390×844
折叠 344×882 · 平板竖 768×1024 · 平板横 1024×768 · 折叠内屏 673×841
手机横 844×390 · 手机横 736×414 · 平板横 1180×820
```

还会输出**布局度量表**（每种设备的 HUD 高度、内容宽、缩放系数），
以及**横屏两栏断言**（确认横屏时标题页真的走了两栏版，而不是碰巧没溢出）。

### 局限（必须知道）

★ 这是**几何检查**，不是像素检查：
- 它能证明「元素没越界、没被遮挡」，**证明不了「好看」**
- 它不检查颜色对比度、不检查视觉层级、不检查动效
- ★ 布局是否真的「居中好看」，必须**人眼看**

## 三、真机调试（★ 上架前必做）

### 3.1 装到真机

```bash
node tools/build-android.js          # 构建
cd app/android
./gradlew installDebug               # 直接装到连着的设备
```

或者把 `releases/*.apk` 传到手机手动装。

### 3.2 打开 WebView 调试

App 是 Capacitor WebView，**调试入口默认关闭**（release 构建）。
debug 构建会自动开：

1. 连 USB，手机开「USB 调试」
2. 电脑 Chrome 打开 `chrome://inspect`
3. 找到 `com.bubbletycoon.game` → 点 **inspect**
4. 就能像普通网页一样看 Console / Elements / 断点

> ★ **Console 里能看到的**：`VIEW` 对象（含 `VIEW.ins` 实际值）、
> `__MINIGAME` 导出、`CV` 工具集。

### 3.3 逐项检查清单

#### A. 尺寸变化（★★ 最重要，本轮修的重点）

| 操作 | 期望 |
|---|---|
| **旋转手机**（竖 → 横 → 竖）| 画面**立即重排**，不拉伸、不变形 |
| 旋转时看 Console | 应有尺寸重算，**不应有报错** |
| **Android 12+ 分屏** | 拖动分屏条时画面跟随变化 |
| **折叠屏展开/折叠** | 展开后布局变成宽屏版（内容居中限宽） |
| 旋转后点「研发」「员工」等 tab | 按钮位置与画面**完全对得上**（验证点击区没偏移）|

> ★ **点击区偏移**是本轮修的一个隐蔽问题：
> 平板限宽居中后，绘制位置平移了，但命中区没跟着平移 →
> 「画在中间、点在左边」。所以**旋转/展开后务必逐个点一遍按钮**。

#### B. 安全区

| 机型 | 检查 |
|---|---|
| 刘海屏（iPhone 14 / 小米 13 等）| 顶部 HUD **不被灵动岛/挖孔**压住 |
| 手势导航机型 | 底部「暂停 / 开门营业」**不被手势条**盖住，能点到 |
| 三键导航机型 | 底部按钮不被导航栏压住 |
| 平板 | 顶部/底部无异常留白 |

> ★ 验证手势条：底部按钮**按下去有没有反应**。
> 看得见但点不到 = 被盖住了。

#### C. 文字

| 检查 | 期望 |
|---|---|
| 320 宽小屏 | 标题页副标题**不溢出**（会被截成「…」但不出屏）|
| 平板上打开各面板 | 一行文字**不超过约 40 个中文字**（限宽 640 的效果）|
| 长名字（配方名、员工名）| 截断处是「…」且**不换行错位** |
| 中英混排 | 不断词（英文在空格处断）|

#### D. 布局与视觉

| 检查 | 期望 |
|---|---|
| 平板竖屏 | 内容**居中限宽**，左右留白对称 |
| 平板横屏 | 同上；六个 tab 与 HUD **对齐** |
| 手机横屏 | 标题页**两栏**（左：品牌+难度，右：存档+信息）|
| 手机横屏的游戏内 | HUD 在上、tab 在下、面板可滚动 |
| 各 tab 切换 | 布局不跳动、内容不错位 |

#### E. 触控

| 检查 | 期望 |
|---|---|
| 快速连点 | 响应灵敏，无 300ms 延迟 |
| 按钮热区 | 手指粗也能点中（视觉外扩 3px）|
| 横屏下点 tab | 点哪切哪，**不偏** |

## 四、Android 侧配置说明

### 4.1 沉浸式与 edge-to-edge

`app/android/.../MainActivity.java`：

```java
WindowCompat.setDecorFitsSystemWindows(getWindow(), false);   // 内容全屏
controller.hide(WindowInsetsCompat.Type.systemBars());          // 隐藏系统栏
controller.setSystemBarsBehavior(BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE);  // 上滑临时唤出
```

★ **为什么不用 `FLAG_FULLSCREEN`**：它只隐藏状态栏，导航栏还在。
而 targetSdk 35 → **Android 15 强制 edge-to-edge**，系统栏一律覆盖在内容上，
导航栏会盖住底部按钮。

★ 上滑唤出系统栏后，WebView 会收到 resize → 触发重排（见下）。

### 4.2 屏幕方向

`AndroidManifest.xml`：

```xml
android:screenOrientation="unspecified"
```

★ 从 `portrait` 放开的原因：
- Google Play 对**大屏适配**有要求，锁竖屏影响商店评分与推荐
- 平板用户横持是常态
- ★ 旋转后的拉伸问题已在 Canvas 版修好（resize 处理）

★ 用 `unspecified`（跟随系统）而不是 `sensorLandscape` ——
后者会**强制横屏**，竖着拿手机的玩家会晕。

### 4.3 resize 处理（Canvas 版的关键）

Android 的 `configChanges` 含 `orientation|screenSize` →
**旋转时 Activity 不重建**，只 resize WebView。

而 Canvas 版原先只在 `boot()` 时算一次 `CW/CH` →
旋转后 canvas 被浏览器拉伸到新视口，内部坐标还是老的 → **画面变形**。

现在 `main.js` 监听三种信号：

```js
window.addEventListener('resize', handleResize);
new ResizeObserver(handleResize).observe(canvas);
window.addEventListener('orientationchange', handleResize);
```

`handleResize()` 会：
1. 清安全区缓存（旋转后刘海/指示条位置会变）
2. 重算 `CW/CH` 与安全区
3. 重建 canvas 尺寸与 DPR 变换
4. 立刻重绘一帧

★ **代价**：重设 `canvas.width` 会清空画布 → 一帧闪白。下一帧 rAF 会立刻补上，
肉眼几乎看不出。若要彻底消除，可用双缓冲（离屏 canvas 交替）。

## 五、如何改布局（给后续维护）

### 布局的唯一真源

```js
minigame/src/ui.js → layoutOf(W, H)
```

它返回：

| 字段 | 含义 |
|---|---|
| `W` `H` | 视口尺寸 |
| `hudH` `tabH` | HUD / tab 栏高度（已含安全区上边距）|
| `bodyY` `bodyH` | 内容区顶与高度（**已减掉底部安全区**）|
| `padTop` `padBottom` | 安全区上下边距 |
| `scale` | 缩放系数（窄屏 0.94~1.10，宽屏 1）|
| `wide` `short` `foldable` | 视口分类 |
| `contentX` `contentW` | 内容区（宽屏时居中限宽 640）|
| `padX` `innerW` | **内容区内的左右边距与可用宽度** ← 各面板用这个 |

### ★ 各面板应该用 `L.padX` / `L.innerW`，不要用 `W - 32`

```js
// ✘ 错：宽屏上会铺满 992px，文字一行太长
var x = 16, w = W - 32;

// ✔ 对：限宽居中后自动正确
var x = L.padX, w = L.innerW;
```

### ★ 绘制与命中必须用同一个 x

```js
GFX.button(ctx, x, y, w, 44, '…', {...});   // 画在 x
GFX.addHit(x, y, w, 44, 'act', ...);        // ★ 命中也必须在 x
```

★ `GFX.addHit` 记录的是**绝对坐标**，`ctx.translate` 对它无效 ——
所以**不能用平移上下文来做居中**，必须改坐标本身。

### 字号用 `fs(L, 'key')` 而不是 `FS.key`

```js
text(ctx, '…', x, y, { size: fs(L, 'sm') });   // ✔ 跟随缩放
text(ctx, '…', x, y, { size: FS.sm });          // ✘ 固定像素
```
