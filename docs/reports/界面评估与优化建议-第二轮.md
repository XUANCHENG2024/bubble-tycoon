## 二、问题清单（按严重度）

### 🔴 高 P0：4 处字号低于 10px，违反刚建立的令牌体系

```
styles.css:1165  .store-badge     font-size: 9.5px
styles.css:1181  .store-mgr-lv    font-size: 9.5px
styles.css:1210  .store-up-lv     font-size: 9.5px
styles.css:1235  .map-dish        font-size: 9px
```

**全部出现在 V12/V12.1/V13 新增段里。**

上一轮刚把 Canvas 端 66 处 <10px 全部提到 10px，并确立了「字号令牌」体系；
这次写新模块时又手写了 `9.5px` / `9px` —— **新代码没走令牌**。

**影响**：中文在 9px 下笔画糊成一片（尤其 `.map-dish` 的 🍜 标记、
`.store-mgr-lv` 的 "Lv.3 正式店长" 这类**要读的字**，不是纯装饰）。

**这是"规范存在但没被强制"的典型**：令牌建好了，但没有机制阻止新代码绕过它。

### 🟠 中 P1：`.btn-xs` 触控目标约 20px

```css
.btn-xs { font-size: var(--fs-xs); padding: 3px 8px; border-radius: 7px; }
```

实际高度 ≈ 3+3+12(line-height)+2(border) = **20px**。

**全部 14 处 `btn-xs` 都在 V12/V13 新增模块里**（店铺卡的接管/撤下/注资/提现/改名/关店、
升级区的购买、待聘区、请回、地图信息卡、店长候选）。

参考：微信小程序建议 44px、Apple HIG 建议 44pt。
**低于 32px 在中低端机上误触率明显上升** —— 而这批按钮全是高频操作
（注资/提现/关店，其中"关店"还是不可逆操作）。

上一轮报告提过这一项，但当时全部 `btn-xs` 都在既有模块里；
现在这 14 处全是我新加的，**优先级应当提高**。

#### ★ 这条检查自身踩了两个坑（都修好了）

**坑一：范围过宽会让断言一上线就是红的。**
初版扫全项目，结果报出 34 处（含 10 处历史遗留）。
**一次全查 = 断言永远红 = 等于没有断言**（大家会习惯性忽略红色）。
所以改成**只卡新增代码**，历史遗留单列在报告里作可选清理项。

**坑二：判据写错，防线抓不到自己要抓的东西。**
初版判据是 `v >= 10 && v <= 22`（只拦令牌区间内的值）——
于是 `9.5px` **被放过了**，而 9.5px 恰恰就是这次要修的问题本身！
也就是说那条断言**根本抓不到 9.5px**。
正确判据：字面量一律不行（>22px 的展示级特例除外）。

> 修正后做了**注入验证**：故意写回 `font-size: 9.5px` → 断言报出 1 处 ✔
> → 移除 → 转绿 ✔
> **没验证过的防线等于没有防线。**

## 六、新增：防「改完又长回去」的不变式检查

这轮做了三件修正界面的事（按钮加高、地图收进弹窗、颜色收敛），
但**没有机制防止下次改代码时又退回去** —— 按钮变矮、地图重新铺开、
颜色又硬编码，都是很自然的手滑。

`tools/diag-ui.js` 新增三条不变式（判据取**可量化的下限**，不取具体数值）：

```
① 触控目标：.btn-xs 的 min-height ≥ 26px
② 商圈页：renderRival 只许调入口条函数，不许调弹窗函数
③ 新增段：不得出现裸 hex
```

### ★ 这条检查自己又踩了三个坑（都靠注入验证抓出来）

**坑一：判据查的是"字面量"而不是"行为"。**
②最初查「renderRival 函数体里有没有 map-svg 字面量」——
注入时把 `cityMapPanelHtml(s)` 换成 `cityMapModalHtml(s)`，
函数体里根本没有 map-svg 字符串，**判据漏掉了**。
正确判据是「调用了哪个函数」。

**坑二：剥注释破坏了行号。**
①要剥掉注释才能正确匹配属性（否则被注释掉的 `min-height` 仍会被匹配到），
但剥注释会改变行数 → 找分段标记时标记本身被删掉 → `from2=0`
→ **整份文件都被当成"新增段"**，报出 7 处假违规。
正确做法：**行号按原文算，匹配时再逐行剥注释**。

**坑三：注释里写了 `*/` 提前结束块注释。**
`/* 不能再出现 /* min-height: 28px */ 这种 */` —— 第一个 `*/` 就把注释结束了，
后面的代码被当成代码解析 → SyntaxError。

### 注入验证（三条全部抓得到）

| 注入 | 结果 |
|---|---|
| ① 把 `min-height: 28px` 注释掉 | ✔ 报「.btn-xs 没有 min-height」 |
| ② 把 `cityMapPanelHtml` 换成 `cityMapModalHtml` | ✔ 报「rival 页又直接渲染了完整地图」 |
| ③ 新增段加裸 hex | ✔ 报「新增段有 1 处裸 hex」 |

**没验证过的防线等于没有防线。**

**P1-1 + P1-2 建议一起做**（约 40 行）—— 两者都指向同一页：
P1-2 把地图收进弹窗后，rival 页变短，P1-1 的按钮变高就不会更挤。
先做 P1-1 会让这个问题更明显。

### 需要真机确认的项

- P1-1 的 28px 在中低端机上是否够（建议真机点几次）
- P1-2 改完后 rival 页的滚动长度是否合适
- 地图 SVG 在 320px 窄屏下的可读性（jsdom 量不了实际缩放）

## 五、附：本轮为什么逐个核对

上一轮报告写「31 种硬编码色绕过变量体系」，**逐个看之后发现 30 种是
变量定义或渐变端点**（如 `#ffc247` 是 `--amber` 的定义、
`#f59e0b` 是 `.btn-amber` 渐变的起点）—— 真正的问题只有 1 处。

**数字大不等于问题大。** 评估必须逐个核对，否则会把「30 处正常」
报成「30 处隐患」，反而让人不敢动。

本轮所有数字都经过逐个核对：
- 硬编码色：31 → **5 处**（逐行看上下文分类）
- 圆角：15 种，但新增段与既有段**同构** → 非新引入
- 字号 <10px：4 处，**全部在新增段** → 是本轮自己引入的
