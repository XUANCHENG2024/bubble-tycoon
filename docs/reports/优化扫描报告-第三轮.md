## 二、性能实测：推翻了三个"阻断级"，确认了一个真要紧的

```
tick 每帧              0.0001 ms  = 帧预算的 0.0%（即使 ×10 也是 0.0%）
slotInfo 记忆化后       0.0005 ms  = 标题页每帧 6 次共 0.003 ms
saveGame               0.041 ms   = 5 秒一次的自动存档无压力
sanitizeState(20天局)   0.33 ms
一整天完整模拟           0.74 ms
```

两个结论：

1. **上一轮扫描报的三个"阻断级性能问题"（每帧重算建议 / gfx 缓存污染 / slotInfo 每帧 6 次净化）全部被实测推翻** —— 绝对值都在帧预算的 1% 以下。
2. **唯一真正要紧的是 slotInfo**：若没有记忆化，低端机（×10）标题页每帧 19.85ms = **帧预算的 120%，会掉帧**；记忆化后 0.025ms = 0.15%。也就是说：**上一轮我顺手做的那次优化恰好是唯一真正救场的一个**——但它当时也只是被静态分析推出来的。现在有了基准，以后任何性能改动都有 before/after 可比。

bundle 279 KB → **gzip 后 98.2 KB**（README 里"约 1/3"的说法实测准确），小游戏首屏包限制内。

## 三、平衡实测：成就现金占了经济的 50~60%，77% 塞在前 3 天

测量踩了两个坑（都记进了探针注释）：不能注钱（会直接达标触发 a_goal 污染数据）；**`tick` 内部已调 `endDay`，循环外再调会把 `newAchList` 覆盖成空**——第一版测出"零成就"就是这么来的。

修复前的数据：

| 阶段 | 成就现金累计 | 占净资产 |
| --- | --- | --- |
| 第 1 天 | ¥773 | 41% |
| 前 3 天 | ¥1810 | 51% |
| 前 30 天 | ¥2510 | 57% |

首日 ¥773 = **开局资金的 107%**。罪魁是 `a_nolost`（¥600）：门槛"12 杯且零流失"在客流只有 10~16 杯的第一天太容易——**53% 的第一天都能白拿**。

**修复**：门槛 12 → 24 杯（描述同步改）。效果：首日注入 ¥773 → **¥320**；达标率 169/91/71（基线 174/92/70，噪声内）；连玩曲线三轮全平、零破产。零流失日从"第一天白送"变回"经营上轨道后的好日子"。

## 四、清理落地（全部经 grep 交叉验证零调用）

| 项 | 说明 |
| --- | --- |
| H5 `doAct` 三个死分支 | `start` / `continue` / `export` —— 标题页这三个按钮是直接 `addEventListener` 绑定的，委托路径永远到不了 |

| `sim.trafficMul` 死字段 | 写入后无人读；真路径走 `s.eventTrafficMul`。删掉的是重复状态，不是功能 |

**注意**：只删了 H5 的死分支——小游戏的 `start`/`continue` 是活的（标题页 hit 区直达），这是两版交互方式的差异。

## 五、一个重要的反例：扫描报告的"零风险"也可能错

Explore-1 建议"把 caps.js 里硬编码的 2147483647 换成 `CFG.RANK_SCORE_MAX`"，理由是"caps.js 排在 data.js 之后，能拿到 CFG"。

**照做后排行榜上报全变成 "NaN"**，被 minigame-smoke 抓到。根因：**caps.js 的 IIFE 内有它自己的 `var CFG`（平台配置：sidebar / adUnitId / rank...），遮蔽了 data.js 的游戏 CFG**——`CFG.RANK_SCORE_MAX` 在那个作用域里是 undefined，`Math.min(undefined, x)` = NaN。

正确做法：复用引擎的 `rankScore()`（顶层函数声明不受 IIFE 内 var 遮蔽）。修复后上报序列 `38402 / 0 / 2147483647 / 1235` 全部正确。

**这个项目里存在两个同名 CFG 对象，是结构性陷阱** —— 以后任何"引用 CFG.xxx"的建议都必须先确认指的是哪一个。
