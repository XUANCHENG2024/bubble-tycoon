## 一、同类热门作品及其关键设计特征

### 1. 开罗《创意咖啡厅物语》/《咖啡馆物语》

| 维度 | 设计特征 |
|---|---|
| 核心循环 | 采购 → 制作 → 接待 → 收款 → 升级设施/员工/菜单 |
| 特色系统 | **PV（魅力值）系统**：装修与设施升级直接决定客流量与满意度 |
| 员工设计 | 4 个数值（服务/感染力/烹饪/品味）+ **8 种特长**，**特长分两组**：大堂组（大力/研究者/撒娇/快走）与后厨组（咖啡大师/红茶大师/果汁大师/烹饪师）—— 决定你把他放哪 |
| 数值成长 | 技能等级**不可超过角色等级**，升级后有冷却 |
| 留存 | 顾客「常客度」上限 100，满意度满则**提高顾客预算**（回头客花更多钱）→ 常客度↑ → 咖啡厅人气↑ → 到店顾客↑ 的正循环 |

**流行原因**：像素画风亲和 + 系统层层咬合（员工→出品→顾客→人气→客流），每个决策都有可见反馈。

### 2. 《Lamar – Idle Vlogger》（放置经营典范）

| 维度 | 设计特征 |
|---|---|
| 核心循环 | 点击赚钱 → 投资自动化 → 解锁更高层 |
| 美术要点 | **升级都是具象化的视觉呈现**（从破旧后院到豪华场景），不是抽象数字 |
| 离线收益 | 刻意设上限且**完全透明** |
| 留存 | 73% 日活每天回归 ≥2 次；靠"阻力系统"——既不自动化到底，也不让玩家卡关 |

**流行原因**：让玩家**看见自己的身份升级**，触发"视觉进步 = 情感投入"的循环。

### 3. 《暮夜传说》/ 放置卡牌类

| 维度 | 设计特征 |
|---|---|
| 核心循环 | 挂机产出 + 手动策略（关卡难度递增限制推图速度） |
| 羁绊系统 | 五种族技能互相克制/增益，战前组合布阵形成**流派**（如"暴击追杀流"） |
| 深度来源 | **没有绝对最强技能**，看官方给的"推荐搭配"标签学习 build |
| 留存 | **无体力系统**；离线不损失；上线自动提示领取 |

**流行原因**：策略深度与轻量操作平衡；收集+规划乐趣，不肝。

### 4. 《口水三国》（元素反应）

| 维度 | 设计特征 |
|---|---|
| 核心机制 | **技能树 × 羁绊网**：主动技能激活被动天赋，同阵营触发共鸣 |
| 纵深 | 五行相生相克（水+火=蒸发 200% 真伤），组合效率比单发高 47% |
| 留存 | 秘境每 10 层三选一祝福，改变 build 方向 |

**流行原因**：用"机制组合"替代"数值堆砌"，策略博弈替代比战力。

### 5. 《超市模拟器》/ 零售经营类

| 维度 | 设计特征 |
|---|---|
| 顾客系统 | 三类顾客（价格敏感/品质追求/便利偏好），**同一满意度因素权重因顾客类型而异** |
| 反馈链 | 满意度 → 购买量 & 离店评价 → 店铺评分 → 新客进店意愿 |
| 深度 | 顾客路径受货架布局影响 → 空间规划有意义 |

**流行原因**：把"顾客满意度"做成多因子加权，而不是单一分数。

### 6. 《鲜多多水果店》/ 轻量经营

| 维度 | 设计特征 |
|---|---|
| 细节张力 | 水果有**保质期**，放太久贬值甚至损坏 —— 简单的规则带来真实的紧张感 |
| 留存 | 体力系统（限制连续游玩）+ 离线收益 + 每日签到 + 成就 + 限时活动 + 轻社交（赠送体力/逛店） |
| 已知问题 | 前期无店员，玩家全程手动，顾客多时手忙脚乱 → **新手流失** |

### 7. 《房产大亨》/ 放置合成

| 维度 | 设计特征 |
|---|---|
| 核心循环 | 合成升级 + 地块竞拍 + 城市地图解锁 |
| 关卡设计 | 每张地图有**专属地标开发任务**；梯度平缓（前期小额合成积累，中后期多地块同时运营 + 竞品竞价） |
| 福利 | 每日签到 / 限时活动 / 好友互助，**不氪金也能拿到高级材料** |

### 8. 《动物餐厅》/ 治愈系经营

| 维度 | 设计特征 |
|---|---|
| 节奏 | 完全佛系，**无强制任务**、无强制广告弹窗 |
| 留存 | 装饰收集 + 慢节奏情感陪伴 |

**启示**：轻与重是两条路；本作定位是**策略向**，不宜照搬佛系，但"不逼氪、不强制"这点应保持。

**真正的缺口**（对照后只剩这几个）：

| 缺口 | 同类做法 | 严重度 |
|---|---|---|
| **店长特性完全独立，没有组合概念** | 开罗：特长分组搭配；放置类：羁绊共鸣 | 🔴 高 |
| 无「回头客/常客」概念（口碑只影响客流，不影响单客消费） | 开罗：常客度↑ → 顾客预算↑ | 🟠 中 |

| 限时活动/每日事件 | 鲜多多：限时节日活动 | 🟡 低 |

## 四、已落地的改进（A1 + B1 + C1）

### 4.1 数据层：`js/data.js` 新增 `MANAGER_COMBOS`

```js
const MANAGER_COMBOS = [
  { id: 'brand',   name: '品牌组合', traits: ['qc', 'hosp'],
    desc: '品质把关 + 宾至如归 = 标准化出品 + 好服务',
    mul: { sat: 1.08, rep: 1.06 } },
  { id: 'leanOps', name: '铁三角',   traits: ['ops', 'lean', 'qc'], ... },
  { id: 'academy', name: '学院派',   traits: ['trainer', 'qc'], ... },
  { id: 'chain',   name: '连锁班底', traits: ['multi', 'ops', 'lean'], ... },
  { id: 'service', name: '服务样板', traits: ['hosp', 'trainer'], ... },
];
```

设计约束（写进注释，避免以后变成随机配对表）：
① 每个组合有**经营内在逻辑**；② **跨店**生效（本作核心是开分店）；
③ 加成克制（单项 ≤10%）；④ 有可读名字，玩家能自己推理。

### 4.2 引擎层：`js/engine.js`

- `managerComboView(s)` —— 哪些组合已激活 / 还缺什么
- `managerComboBonus(s)` —— 组合乘数
- `managerBonus(s, branch)` —— **乘上组合乘数**（两层结构）

```
单店特性（ops/qc/lean/hosp）→ 只作用于他那家店（个人层）
组合加成（brand/leanOps/…） → 所有店都吃到（团队层）
```

玩家决策因此变成两件事：**招什么特性** + **放谁去哪家店**。

### 4.3 表现层：两版对等

- **H5**（`js/ui.js` + `styles.css`）：管理页顶部「团队组合」面板，5 个组合全列，已激活高亮 + 未激活显示"还缺谁"
- **Canvas**（`minigame/src/ui.js`）：**紧凑版** —— 只画"已激活"+"最接近凑齐的一个"（5 个组合 × 3 行会把分店列表推出裁剪区）

### 4.4 回归锁

**probe U 组（14 项）**：
- U1 组合表合法（特性 id 在字典内 / 乘数 >1 / ≤10%）
- U2 未招人时不生效
- U3 逐个组合验证"集齐即激活且加成真的进 managerBonus"
- U4 候选池不触发（还没上任）
- U5 脏存档的假特性凑不出组合
- U6 存档往返后组合仍在

**browser-smoke（6 条）** + **minigame-smoke（7 条）**：面板存在、状态可读、组合面板在分店列表之前（招人前先看到目标）、Canvas 显示具体数值。

### 4.5 写这个功能时抓到的两个 bug

**① 未激活的组合也发加成**（`managerComboBonus` 漏判 `c.active`）
→ 被 probe U2c「没招店长时组合乘数全为 1」直接照出来。
这个 bug 若漏网，玩家不开分店就能白拿 24% 满意度加成。

**② Canvas 端假断言**
最初写「分店区命中区 ≥1」，实测发现 **`mmove` 一直是 0** ——
管理页本来就超一屏（店长区在靠后位置），**与组合面板无关**。
用绝对数量断言会得到一个**永远红的假断言**，反而让人忽略真正的红线。
改成「命中区数 ≥ 基线 26 个」——守的是"组合面板没让可见内容变少"。

> ★ 两次都是断言的**判据**有问题，不是代码有问题。
> **判据错了，测试就会变成噪音或假绿。**

## 七、V13.5 ~ V13.7 的关键发现

### 1. 数值必须**实测扫参**，不能拍脑袋

常客系统调了四轮才定稿（跑真实 30 天 AI 局，反复调 gain/max/身份数）：

| 配置 | 结果 | 判定 |
|---|---|---|
| 20 身份 + gain 2 | **20/20 全满** | 退化成人人常客，加成对所有人一样 = 没区分度 |
| 100 身份 + gain 2 | **0 位常客** | 摊太薄 |
| 100 身份 + gain 5 | **约 13~21 位常客** | ✔ 定稿 |
| 100 身份 + gain 6+ | 20~42 位 | 波动大 |

店长专精同理：初版 `+20%/-10%×3` = **净 -10%**（越专精越差），
玩家根本不会用这个机制 → 改成 `-5%`（净 +5%）。

### 2. 有些"设计"其实是**数学死锁**

初版常客有「每日衰减 -1」的设计，看着像"不常来会淡忘"：
- 顾客 2 天来 1 次 → 每 2 天净 -2 +2 = **0** → 永远卡在 92，满不了
- 3 天来 1 次 → 净 -1 → 越攒越少

30 天实测确实有两位卡在 96/92 永远成不了常客。
**开罗原作的常客度不衰减** —— 它是「累积的里程碑」不是「易变的状态」。

### 3. 断言的**判据**比代码更容易错

这一轮三次踩到：
- `mmove >= 1` → 永远红的假断言（管理页本来就超一屏）
- 「主店/分店」tab 搞错 → 测的是另一个面板
- 「有代码味词汇才算泄漏」→ 注入测试抓不到

★ 判据错了，测试就是噪音或假绿。

### 4. Canvas 端与 H5 端有**真实交互差异**

H5 页面原生滚动，Canvas 要自己滚（`VIEW.scroll[tab]`）。
测 Canvas 端店长区的专精按钮时，**不滚动就查不到命中区** ——
一度以为功能没实现，其实是内容在屏幕外。

★★ Canvas 端的老坑（又踩一次）：**卡片高度必须跟着内容涨**。
专精按钮画在卡片外 → `GFX.addHit` 在裁剪区外不登记 →
「画出来了但点不到」（招牌卡/研发树/出杯位/V13 地图/团队组合面板都栽过）。
minigame-smoke 的「专精按钮已注册命中区」+「点专精按钮真的生效」两条断言就是守这个。
