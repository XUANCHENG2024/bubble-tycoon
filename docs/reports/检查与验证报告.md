## 二、阻断级问题（P0，6 项）

### P0-1 标题页三个入口点击后毫无反应

- **位置**：`js/main.js:18` 的 `TITLE_ACTS` 白名单
- **表现**：停在标题页时点「🔥 连续登录」、存档槽选择器、「导入并继续」三个按钮，**完全无反应，也不报错**
- **成因**：事件委托里有一道守卫 `if (window.S === null && !TITLE_ACTS.includes(act)) return;`。它本意是挡住依赖 `window.S` 的动作，但 `login`（只读 META）、`slot`（只读 `slotInfo`）、`doimport`（先 `importSave` 再交给 `startGame`）三个分支**根本不读 `window.S`**，却被一起吞掉了
- **为什么测试没抓到**：四套冒烟都是直接调 `doAct(...)`，绕过了这道委托守卫。只有真实 `.click()` 才会走这条路径
- **修复**：补全白名单，并在注释里写明准入条件（"该分支不读 window.S"）
- **验证**：`browser-smoke` 新增 8 项真实点击断言。**特意做了反向验证** —— 把修复回退后，这 8 项里有 4 项立刻失败，确认测试真的有效

### P0-2 XSS：`s.news.text` 未转义，导入存档即可执行

- **位置**：`js/ui.js:376`
- **表现**：这是全项目**唯一一处**把动态文本拼进 `innerHTML` 却漏掉 `esc()` 的地方。存档可导出/导入，一份带 `<img src=x onerror=...>` 的存档就能执行脚本
- **成因**：`sanitizeState` 对 `news.text` 只做了限长，渲染层又忘了转义
- **修复**：`${esc(s.news.text)}`

### P0-3 XSS：`adviceOf()` 里拼对手名未转义

- **位置**：`js/engine.js:2055`
- **表现**：整段文案自带 `<b>` 标签，渲染层看到 `<b>` 就整段放行，于是插值进来的 `s.rival.name`（来自存档）原样变成 DOM
- **修复**：引擎是纯逻辑层拿不到渲染层的 `esc()`，因此在 `engine.js` 内新增 `escText()`（与 `esc()` 同规则），只对插值进来的对手名转义

### P0-4 顶层符号重名导致 H5 白屏（**本轮修复过程中我自己引入的回归**）

- **位置**：`js/engine.js` 与 `js/ui.js` 各声明了一份 `ESC_MAP`
- **表现**：修复 P0-3 时我在 `engine.js` 加了 `ESC_MAP`，与 `ui.js:11` 已有的那份重名。经典脚本的顶层 `const/let` 落在**同一个全局词法环境**里，同名重复声明**不是覆盖，而是让后加载的 `ui.js` 整份解析失败** —— H5 端白屏，控制台只留一句 `Identifier 'ESC_MAP' has already been declared`
- **修复**：`ui.js` 删掉自己那份，改为 `const esc = escText;` 取别名。这比"给引擎里那份改名"更彻底 —— 两份常量变一份，且与 `ui.js` 里"**`num()` 由 engine.js 统一提供，此处不再重复声明**"的既有约定一致
- **防复发**（三层）：
  1. 新增 `tools/symbol-check.js`：按真实加载顺序拼接后交给 V8 解析，零误报
  2. `dom-smoke` 加载前扫一遍各文件的顶层 `const/let`，重名直接点出是哪两个文件
  3. `build-minigame.js` 打包前自检，语法错误直接 `exit 1`，不会产出坏 bundle

### P0-5 `endDay()` 在 `s.sim === null` 时崩溃

- **位置**：`js/engine.js:852`
- **表现**：`const sim = s.sim;` 无守卫，prep 阶段（或开门被拒后）调用直接抛 `Cannot read properties of null (reading 'revenue')`。结算是主流程必经的一步
- **修复**：`if (!s || !s.sim) return null;`

### P0-6 非法 id 让升级/开店直接抛异常

- **位置**：`js/engine.js` 的 `upgradeCost` / `shopCost`
- **表现**：`upgradeById(id)` 返回 `undefined` 时读 `.max` 抛错；`s.up[id]` 为 `undefined` 时 `Math.pow(mult, undefined)` 得到 `NaN` 并一路污染现金；`s.shops` 为 0 时 `SHOP_COSTS[-1]` 是 `undefined`
- **修复**：三处都加了守卫，等级改用 `pos(s.up[id], 0)` 收敛

## 五、测试有效性修复（3 项，值得单独说）

### 27. `xss-verify` 的断言是"虚假安全感"

原脚本用 `window.__PWN` 这个 `onerror` 回调来判断注入是否得逞。但 **jsdom 默认不加载外部资源**，`img src=x` 根本不会发起请求，`onerror` 永远不会触发 —— 那条断言恒为 `false`，看着像"很安全"，其实什么都没验。

**修复**：改为数 DOM 里有没有真的出现 `img` / `script` / `svg` / `[onerror]` / `[onload]`。payload 从 3 组扩到 4 组，覆盖日志、员工/候选人名、对手名、新闻文案，并补了**引擎生成的 HTML 片段**这一路。脚本现在会以非 0 退出码失败。

### 28. `probe` 的 E3 基准点取错（查了很久，值得记录）

探针报"当日现金对不上账，差 ¥24"。追查后确认**不是引擎 bug，是探针自己算错了**：`buyIng` 会触发 `bumpQuest('restock')` 发一笔任务奖金，而 `cashBefore` 是在 `buyIng` **之后**取的（已含这笔钱），公式里又加了一次 `questCash`。

排查手段：给 `s.cash` 挂 `defineProperty` setter 抓每笔入账的调用栈，跑 300 次定位到差额恒为 24，再对照任务表确认来源。

**修复**：基准点统一到"开门前一刻"，`questCash` 只统计开门之后的增量。

### 29. `probe` 的 E1 被 `marketing=0` 掩盖

原断言把营销费扣了两次（`rep.marketing` 和 `s.dayMarketing` 是同一个值），但因为测试里营销费恰好是 0，断言"因为没得可扣"而轻易通过 —— 账目校验变成了走过场。**修复**：测试里故意投一笔 ¥60 营销费，并断言"当日营销必须大于 0"。

## 七、整体状态结论

### ✅ 可以正常运行

- 构建通过，两版都能跑通完整主流程（标题页 → 备货 → 营业 → 结算 → 次日 → 收官）
- 8 套测试套件连跑 3 轮全绿，共 366 项断言
- 数值平衡与基线一致
- 安全：4 组 XSS payload 全部作为纯文本存在；存档清洗器覆盖了 38 个字段 × 24 种脏数据

### 遗留问题说明

**1. 真机验证尚未进行（唯一的功能性遗留）**

已按方案备好验证清单，仍等用户提供两款测试设备的机型与系统版本。以下平台能力**必须真机验证**，模拟器测不出来：

- 抖音排行榜（`tt.setImRankData` / `getImRankList`，且要求先 `tt.login`）
- 内购、添加到桌面、侧边栏复访（`tt.navigateToScene`）、订阅消息、广告

**2. 包体**：278.8 KB（纯文本 JS）。gzip 后约 90 KB，小游戏首屏包限制内，无需处理。

**3. 已知但不修**（有意为之，非缺陷）：

- 成就每局都会重新发放现金（`s.ach` 每局新建）—— 这是 F1 的设计：★ 只在跨局首次给，现金是即时反馈
- 新档第一天成就现金注入偏大（实测 ¥600~1900），会让早期难度略宽松 —— 属于数值调优，留到下一轮配合 F4/F5 一起做
- `minigame-smoke` 总数在 173/174 间浮动 —— 随机事件那一项只在当天真的触发事件时才计入

**4. 方案中已排期、本轮未实现的功能**（不属于缺陷）：

- P0：B1 三层目标 HUD
- P1：F4 解锁树 / F5 难度解锁链与专家词条 / B2 成就分级 / B3 结算评分卡 / F6 rubber band / F9 无尽词条化
- P2：F7 单局 30→21 天 / F8 分享口令 / F10 异步互访

**5. 用户侧待办**：主体类型、软著、ICP 备案、4~6 张 1080×1920 截图、隐私政策/用户协议里的联系方式占位替换。
